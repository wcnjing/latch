# Console fixtures

**These are scripted, not agent output.** The agent core does not exist yet.
They are what it will produce, so workstream C can build the console against
real shapes on day 5 instead of waiting for day 9.

Regenerate after any contract change:

```bash
uv run python scripts/make_fixtures.py
```

They are generated by driving the real domain objects — the state machine, the
lock table, the confidence engine, the trace recorder — rather than by
hand-writing JSON. A fixture that violates a contract therefore cannot be
produced: every state move goes through `transition()` and raises if illegal,
and the contention priorities come out of a real `LockTable` rather than being
typed in. If `models.py` changes and the generator still runs, the fixtures are
still valid.

## Files

| File | Contents |
|---|---|
| `risks.json` | Six `ConnectionRisk` records in wire format — the A → B handoff shape |
| `traces.json` | Six completed traces — the B → C handoff shape |
| `summary.json` | North-star metric with its denominator, and cost per risk |
| `state_diagram.mmd` | Mermaid state diagram, generated from the transition table |

## The six scenarios

Chosen so the console has risks at genuinely different states rather than six
variations of the happy path.

| Risk | Shape | Ends at |
|---|---|---|
| `cr_0001` | Baseline timeout. Tool times out twice, falls back to an 8-minute-old cache, confidence drops to 0.62, gate escalates from vessel ops to duty manager | `connection_held` |
| `cr_0003` | Contention winner. Preempts a lower-priority reservation on the last slot | `connection_held` |
| `cr_0002` | Contention loser. Loses the slot, re-deliberates, finds no alternative, falls to Rung 4 — and the line never answers | `window_lapsed_no_response` |
| `cr_0004` | Dismissed by triage. Six hours late against thirty hours of slack: large delay, no risk | `dismissed_no_action` |
| `cr_0005` | Superseded. ETA improves mid-deliberation and the risk evaporates | `superseded` |
| `cr_0006` | Customer declines every option. The box still rolls — and this is a **success** | `customer_declined_all` |

`cr_0002` and `cr_0006` are the pair worth designing around. Both end with a
rolled box. One is a service failure and one is not, and making that difference
legible on screen is the single most valuable thing the console can do.

## Reading the metric

`summary.json` reports the north star with its denominator, because a rate
quoted bare is not a measurement:

```json
{ "at_risk": 4, "served": 3, "service_rate": 0.75,
  "excluded_dismissed": 1, "excluded_superseded": 1 }
```

Dismissals and supersessions are excluded from the denominator rather than
counted as failures — neither was ever a connection genuinely at risk of
failing, and counting them as failures would punish the system for correctly
deciding there was nothing to do. The exclusions are reported so the choice is
visible rather than buried.

## Notes for the console

- **`terminal_resolution`** on every vessel call is `berth`, `terminal`,
  `inferred`, or `simulated`. Surface it. If the day-1 data gate lands on
  port-level-only data, this field is the difference between a checkable claim
  and an implied one — and it is doing real work, because it feeds confidence.
- **`derived`** on each risk carries `priority`, `slack_consumed_pct`, and
  `crosses_terminals` precomputed. Render those; don't reimplement the
  arithmetic.
- **Confidence steps** carry a `derivation` string. It is designed to be shown
  verbatim next to the number, which is what turns "the agent cannot
  self-certify" from a claim into something visible on screen.
- **Cost** is per-trace, not just per-run, so a single decision can show what it
  cost to make.
